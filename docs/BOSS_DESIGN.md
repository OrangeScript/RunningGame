# 镜庭守望者：首领战与联机更新

正式入口：`Assets/Scenes/Bootstrap.unity`。主菜单新增“首领练习”，可独自直接开始；房间中选择“首领练习”可让 2–4 人同场挑战。爬塔最终节点仍然进入同一场首领战。

## 可玩的规则

| 输入 | 行为 |
| --- | --- |
| WASD | 平面移动，最高速度 8 米/秒 |
| Shift | 精确移动，速度降至 42%，显示小判定点 |
| 鼠标 | 瞄准；左键或空格持续射击 |
| Q / E | 使用第一 / 第二个主动道具；HUD 显示图标、名称和冷却 |
| R | 擦弹能量到 100 后，清除自身 6 米内弹幕并获得短暂护盾 |

角色的弹幕受击判定为平面圆，普通半径 0.22 米，精确移动半径 0.16 米；模型和 CharacterController 用于行走，不代替弹幕判定。弹幕按上一帧到本帧的线段检测，避免低帧率下穿过角色。受击后有 0.6 秒无敌时间。与弹幕擦身而过可以充能，同一颗弹对同一玩家只结算一次擦弹。

镜头使用世界 XZ 平面矩形死区，半宽 4.5 米、半高 3 米。角色离开矩形后，镜头以 0.22 秒平滑追随，在场地边缘限制镜头中心，保留战场可读性。

## 一个首领，三段符卡

基础生命 320；每多一位玩家增加 65% 生命，不按人数加倍铺满弹幕。死亡玩家不再被定向弹锁定，也不能继续开火或使用主动道具。

| 生命 | 符卡 | 读招与应对 |
| --- | --- | --- |
| 100%–70% | 水镜 · 回纹 | 24 发环弹，两个相对的移动缺口。观察缺口随波次缓慢摆动，低速穿行；每波固定留出安全方向。 |
| 70%–35% | 雷幕 · 引流 | 五臂旋转弹与面向存活玩家的三路弹流交替。蓝色细线预告已锁定方向，发射后不追踪；先诱导，再横移，队友避免站到彼此后方。 |
| 35%–0% | 终符 · 镜雨 | 带宽缺口的纵向雨幕、定向弹流和较密环弹交错。提前转向雨幕缺口，留消弹应急，利用破甲窗口集中输出。 |

切换符卡时清除旧弹幕并留出 1.4 秒过渡。弹速、角度、缺口、预警时间由服务器决定，不用随机散射制造必死局。预警期间弹体变浅、变小且没有伤害。定向弹流有 0.75–1.05 秒预警。

## 元素构筑怎样改变解法

首领的元素附着由所有玩家共享，持续 5 秒。反应有全队共享的 0.45 秒冷却，限制多弹、多人的反应堆叠。前两种不同的弹药元素在每发弹体间交替；单人可以自行完成元素接力。

| 配合 | 效果 |
| --- | --- |
| 水 + 火、冰 + 火 | 蒸发 / 融化伤害；反应倍率上限 2 倍 |
| 水 + 冰 | 凝镜，使后续波次间隔变为 1.65 倍，持续 3.5 秒；不冻结已经飞出的弹体 |
| 水 + 雷 | 感电，单次积累 28 破甲 |
| 火 + 雷 | 超载，单次积累 35 破甲 |
| 风、土、草参与 | 扩散 / 结晶 / 绽生，分别积累 18 / 22 / 24 破甲 |
| 不同玩家接力 | 本次破甲积累增加 30%；没有组队也能独立破甲 |

破甲到 100 时，清除全场弹幕、停顿 1.5 秒，并暴露弱点 5 秒；暴露期间基础伤害倍率为 1.8，后续波次间隔变为 1.6 倍。物理攻击始终可造成伤害，元素配合提供更安全、更快的打法。

单人练习预置水、火和空白符。双人练习分别给水 / 群体治疗、火 / 消弹；第三人补冰 / 护盾，第四人补雷 / 雷击。从爬塔进入时完全保留自己实际获得的道具和门的火力，不赠送练习装备。胜负结算后，房主可以“再试一次”，所有玩家可以返回菜单。

## 道具池与图像

全局目录为 `Assets/Resources/ItemCatalog.asset`，共有 44 件道具，本次新增 30 件。新增效果通过 `ModularItemDefinition` 组合武器、元素、生存和主动能力；道具 ID 在跑酷、Arena 和未来第一人称模式之间保持稳定。

- 被动：元素核心、扳机、弹匣、穿甲、回弹、移速、减伤、恢复、擦弹效率等。
- 主动：消弹、团队治疗、护盾、雷击，各自具有服务器冷却。
- 临时：疾风、冰雾、过载、恢复等，按剩余游戏时间到期。
- 高品质：轮转棱镜、冰火熔核、守望之心、不灭星等，只进宝藏奖励池。

普通关内仍只产生门和增幅。永久道具来自关后选择或宝藏；临时道具来自事件。三选一先排除已拥有的唯一道具，再优先避开最近 12 个曾展示的候选；库存不足时按权重回退，同一次展示不重复。

36 个线性图标通过 [Iconify SVG API](https://iconify.design/docs/api/svg.html) 从 Lucide 图标集获取，使用 [Lucide ISC 许可](https://lucide.dev/license)。PNG 随包离线加载，游戏运行不请求网络；原始 SVG 和完整许可保存在 `Assets/ARt/Icons/Lucide`。重建方法：在 `Tools/icons` 下运行 `npm ci`、`node fetch-icons.mjs`。

## 客户端同步修复

Runner 和 Arena 都改为所有者即时预测、服务器确认序号、回放未确认输入。服务器只接收量化输入，不接受客户端位置或伤害。每次发送携带最近 4 条输入抵抗丢包；服务器有时间预算，拒绝重复或超速命令。位置只走一条 30Hz 快照通道，其他玩家做短缓冲插值；移除了与预测争抢根坐标的 NetworkTransform。跑酷换关带位置版本号，旧关卡输入不能作用到新出生点。

Arena 原来的边界处理拿浮点位移做精确比较，合法移动也会反复清零速度；现在只在实际越界时清零对应轴速度。客户端立即生成无伤害射击特效，服务器仍独立验证并处理命中。所有联机端需要使用同一版本的两个 Player prefab。

## 可重复验证

这些入口在独立工程副本中运行，避免结束正在打开的 Unity 会话：

- `RunningBossValidator.ValidateCommandLine`：移动距离、死区边界、输入序号回绕、单人 / 多人反应、奖励去重、44 件道具及离线图标。
- `RunningNetworkPredictionSmoke.BeginHost` / `BeginClient`：两个独立进程，真实 UTP，每端配置 80ms 延迟和 10ms 抖动；检查输入即时响应、开火特效、移动、精确移动、客户端装备与停步后的服务器位置误差。
- `BeginRunnerHost` / `BeginRunnerClient`：同样验证跑酷所有者响应。
- `RunningBossEncounterSmoke.Run`：正式单人练习入口、三段符卡、受击无敌、元素破甲、主动消弹、胜利与重试，并保存实际画面。
- `RunningPlayModeSmoke.Run`、`RunningArenaPlayModeSmoke.Begin`：完整跑酷闭环与跨场景构筑保留的回归。

当前数值是可试玩的初始平衡。符卡难度和不同构筑的收益仍需要真人连续试玩后调节；角色和首领继续使用现有基础模型。
